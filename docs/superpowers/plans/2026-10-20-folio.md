# Folio Implementation Plan
> For agentic workers: use executing-plans to implement this plan task by task.

**Goal:** Deliver a working Korean Notion-inspired personal workspace, validated using tester-army/e2e.
**Architecture:** Buildless browser ES modules and localStorage, served from dist. Separate domain state, UI rendering, event handling, and design tokens. E2E runs real Chromium against the app.
**Tech Stack:** HTML, CSS, JavaScript, Node 22, e2e 0.21.2, @e2e-dev/web 0.15.2.
**Spec:** docs/superpowers/specs/2026-10-20-folio-design.md

## Global constraints
Korean UI; local persistence without credentials; no fake collaboration or AI; user content escaped; mobile support; semantic names for tested controls.

## Review focus
Hierarchy consistency on deletion/restoration; empty and long content; invalid imported files; reload persistence; mobile overflow and keyboard navigation.

### Task 1: Page and editor workflows
Files: dist/store.js (domain and persistence), dist/app.js (render and events), dist/styles.css, dist/index.html; tests/workspace.e2e.ts.
Interfaces: loadWorkspace(), saveWorkspace(state), createPage(state, options), page state with id/title/icon/parentId/blocks/deleted/favorite.
- [ ] Write user-flow tests and run against the empty app, expecting absent UI failures.
