# Folio 개발 가이드: Notion 대비 빠진 기능

작성일: 2026-11-10. 기준 커밋: `aad2dce`. 기준 상태: e2e 67/67 통과, `npm run check` 통과.

이 문서는 검토용입니다. 승인 전에는 코드를 바꾸지 않습니다. "검토가 필요한 결정" 6건에 답을 주시면 1단계부터 진행합니다.

## 1. 검토가 필요한 결정

각 항목의 첫 번째 안이 권장안입니다. 답이 없으면 권장안으로 진행합니다.

| # | 결정 | 권장안 | 대안 |
| --- | --- | --- | --- |
| D1 | 범위 | 1~4단계 진행, 5단계(미디어·표 블록 등)는 4단계 후 다시 결정 | 1~5단계 전부 / 1~2단계만 |
| D2 | 텍스트 서식 방식 | 블록 입력을 `textarea`에서 `contenteditable`로 교체 (Notion처럼 보이는 대로 편집) | `textarea` 유지, `**굵게**` 같은 기호를 그대로 저장하고 표시만 변환 |
| D3 | 저장 형식 | `version: 2`로 올리고 v1 데이터는 열 때 자동 변환. v1 백업 가져오기도 계속 지원 | `version: 1` 유지, 새 필드를 선택 항목으로만 추가 |

## 2. 공통 규칙

- **구조 유지**: 빌드 도구와 프레임워크 없이 `dist/`의 ES 모듈을 그대로 씁니다. `app.js`가 이미 390줄이므로 새 기능은 새 모듈로 나눕니다.
- **테스트 먼저**: 기능마다 e2e를 먼저 쓰고 실패를 확인한 뒤 구현합니다. 기존 67건은 계속 통과해야 합니다.
- **단계별 완료 조건**: 전체 e2e 통과, `npm run check` 통과(새 모듈을 `check` 스크립트에 추가), 데스크톱·모바일 캡처 확인, 단계별 커밋.
- **보안**: 사용자 입력은 지금처럼 전부 `esc()`를 거칩니다. 서식은 HTML 문자열이 아니라 범위 데이터로 저장하고, 화면에 그릴 때 허용된 태그만 만듭니다. 링크는 `http`, `https`, `mailto`만 허용합니다.
- **가져오기 검증**: 새 필드는 모두 `validateWorkspace`에 검증을 추가합니다.
- **삭제 금지**: 파일 삭제 명령은 쓰지 않습니다. 필요 없어진 파일은 옮기거나 먼저 묻습니다.

## 3. 단계별 계획

### 1단계: 편집기 기본기

서식 방식(D2)과 무관하게 지금 `textarea` 위에서 바로 할 수 있는 것들입니다.

| 기능 | 동작 | 구현 메모 |
| --- | --- | --- |
| Markdown 단축 입력 | 블록 맨 앞에서 `# `, `## `, `### `, `- `, `* `, `1. `, `[] `, `> `, ` ``` `, `---` 입력 시 해당 블록으로 전환 | `input` 이벤트에서 접두어 확인. 한글 조합 중(`isComposing`)에는 건너뜀 |
| 새 블록 유형 | 제목 3, 번호 목록, 토글, 코드 | `blockTypes`와 `typeOptions`에 추가. 토글은 `open` 필드, 코드는 고정폭 글꼴과 Tab 입력 |
| 번호 목록 | 연속된 번호 블록에 1, 2, 3 자동 부여 | 저장하지 않고 그릴 때 계산 |
| 들여쓰기 | Tab·Shift+Tab으로 수준 변경, 토글은 하위 블록을 접음 | 블록에 `indent`(0~6) 추가. 트리 구조로 바꾸지 않고 평평한 배열 유지 |
| `/` 메뉴 필터 | `/제목`처럼 이어 쓰면 목록이 걸러지고, 방향키·Enter로 선택 | 지금은 내용이 정확히 `/`일 때만 열림 (`app.js:269`) |
| 빈 목록에서 Enter | 빈 글머리·번호·할 일 블록에서 Enter를 누르면 텍스트 블록으로 바뀜 | 지금은 같은 유형이 계속 생김 (`app.js:319`) |
| 블록 병합 | 블록 맨 앞에서 Backspace를 누르면 앞 블록과 합쳐짐 | 지금은 빈 블록만 삭제됨 (`app.js:320`) |
| 블록 간 이동 | 첫 줄·마지막 줄에서 위·아래 방향키로 이웃 블록 이동 | |
| 블록 복제 | 블록 메뉴에 "복제" 추가, Ctrl/Cmd+D | |
| 실행 취소 | Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z로 블록 삭제·이동·전환을 되돌림 | 페이지별 스냅샷 최대 50개, 메모리에만 보관. 글자 입력은 브라우저 기본 동작 유지 |
| Markdown 내보내기 | 새 유형과 들여쓰기 반영 | `pageMarkdown` 확장 |

테스트: `tests/editor-basics.e2e.ts`, 약 20건.

### 2단계: 텍스트 서식 (D2, D3)

| 기능 | 동작 |
| --- | --- |
| 서식 | 굵게(Ctrl/Cmd+B), 기울임(I), 밑줄(U), 취소선(Shift+S), 인라인 코드(E) |
| 링크 | Ctrl/Cmd+K로 링크 입력. 선택 영역이 없을 때는 지금처럼 검색 열기 |
| 색상 | 글자색·배경색 각 9종 |
| 서식 도구 모음 | 글자를 선택하면 위에 떠서 표시 |
| Markdown 인라인 단축 입력 | `**굵게**`, `*기울임*`, `` `코드` ``, `~~취소선~~` |
| 붙여넣기 | 일반 텍스트로만 받음. 여러 줄은 블록 여러 개로 나눔 |

데이터 형식: `text`는 지금처럼 일반 문자열로 두고, 서식은 `marks` 배열에 따로 저장합니다.

```js
{ id, type: 'text', text: '굵은 글자와 링크', indent: 0,
  marks: [{ start: 0, end: 5, type: 'bold' }, { start: 7, end: 9, type: 'link', href: 'https://…' }] }
```

이렇게 하면 검색과 Markdown 내보내기가 `text`를 그대로 쓸 수 있고, 저장된 HTML을 그대로 화면에 넣는 일이 없습니다.

주의할 점:
- 한글 조합 중에는 DOM을 다시 그리지 않습니다. 다시 그리면 조합이 끊깁니다.
- 지금은 구조가 바뀔 때마다 `render()`가 화면 전체를 다시 만듭니다. 편집기는 바뀐 블록만 고치도록 바꿔야 커서 위치가 유지됩니다.
- 기존 블록 관련 테스트의 `toHaveValue`를 `toHaveText`로 고칩니다.

테스트: `tests/rich-text.e2e.ts` 약 15건, `tests/migration.e2e.ts` 약 5건(v1 저장 데이터 열기, v1 백업 가져오기, 잘못된 `marks` 거부).

### 3단계: 데이터베이스 일반화 (D4)

지금은 `state.tasks` 하나가 모든 데이터베이스 페이지에 공유됩니다. 데이터베이스 페이지를 복제해도 같은 작업을 보게 됩니다.

새 형식:

```js
state.databases = {
  [pageId]: {
    properties: [{ id, name: '상태', type: 'select', options: [{ id, name, color }] }, …],
    rows: [{ id, title, values: { [propertyId]: value }, blocks: [] }],
    views: [{ id, name: '표', type: 'table', filters: [], sorts: [], groupBy: null, hidden: [] }],
    activeViewId
  }
}
```

기존 `tasks`는 "프로젝트" 데이터베이스로 변환합니다. 상태·우선순위는 선택 속성, 담당자는 텍스트, 마감일은 날짜가 됩니다.

| 기능 | 동작 |
| --- | --- |
| 데이터베이스 만들기 | `/` 메뉴와 새 페이지에서 "데이터베이스" 선택. 페이지마다 독립된 데이터 |
| 속성 관리 | 추가·이름 변경·삭제·숨기기·순서 변경 |
| 속성 유형 | 텍스트, 숫자, 선택, 다중 선택, 날짜, 체크박스, URL |
| 선택 옵션 | 옵션 추가·이름 변경·색상·삭제 |
| 보기 | 표, 보드에 더해 리스트, 캘린더, 갤러리. 보기 추가·이름 변경·삭제 |
| 필터 | 여러 조건을 "모두 만족"으로 결합. 유형별 연산자(포함, 같음, 비어 있음, 이전·이후) |
| 정렬 | 여러 속성, 각각 오름차순·내림차순 |
| 그룹화 | 보드는 임의의 선택 속성 기준, 표는 그룹 머리글 |
| 항목 페이지 | 항목을 열면 속성과 블록 본문 편집 (D4) |
| 표 편의 기능 | 열 합계(개수, 합, 평균), 행 순서 드래그 |
| 검색 연동 | 워크스페이스 검색에서 데이터베이스 항목도 찾음 |

제외: 관계형, 롤업, 수식, 타임라인, 다른 페이지 안에 넣는 인라인 데이터베이스. 필요하면 5단계 이후에 다시 논의합니다.

홈 화면의 "프로젝트" 영역은 지금처럼 프로젝트 데이터베이스를 그대로 보여 줍니다.

테스트: `tests/database-model.e2e.ts` 약 25건. 기존 `database-controls.e2e.ts` 9건은 변환된 기본 데이터에서 그대로 통과해야 합니다.

## 5. 지금 알고 있는 위험

- **데이터 손실**: 저장 형식 변환이 틀리면 기존 문서가 깨집니다. 변환 전 원본을 `folio.workspace.v1.backup` 키에 한 번 보관하고, 변환 실패 시 원본을 건드리지 않고 지금의 "저장 안 됨 · 백업 필요" 상태로 엽니다.
- **워크스페이스 보관본**: `folio.workspaces.v1`에 든 다른 워크스페이스의 스냅샷도 v1입니다. 전환할 때 변환해야 합니다 (`workspaces.js`의 `validateWorkspace` 호출 3곳).
- **다른 탭 보호**: 저장 직전에 저장소 문자열을 비교하는 지금의 보호(`app.js:27`)는 그대로 유지합니다.
- **배포본과의 호환**: 새 버전에서 만든 백업은 이전 배포본에서 열리지 않습니다. 배포 전까지 로컬과 배포본의 백업을 섞어 쓰면 안 됩니다.
- **검증 범위**: 테스트는 Chromium만 돌립니다. Safari·Firefox의 `contenteditable` 동작 차이는 확인되지 않습니다.
